# tender-risk-ml

Прогнозирование сорванных договоров в госзакупках Казахстана (goszakup.gov.kz). Семестровый проект по машинному обучению.
English version: [README.md](README.md).

Этапы курса: **A1 Проблема и датасет → A2 Подготовка данных и базовая модель → Мидтерм → A3 Обучение и дообучение моделей.**

## Задача в одном абзаце

Портал госзакупок Казахстана публикует около 1,8 млн закупок в год через OWS v3 GraphQL API. Проверить такой объём
вручную невозможно. В проекте строится **бинарный классификатор**, который по информации, известной в момент выбора
победителя (характеристики закупки, лоты, заявки участников), предсказывает, закончится ли закупка **сорванным
договором**, то есть договором, который расторгнут или не заключён. Индикаторы-правила из прежнего инженерного
проекта (Tender Radar) рассматриваются как кандидаты в признаки, а не как метки, поэтому модель обучается на реально
наблюдаемом исходе.

## Результаты (тестовый период, 16–31 марта 2024)

| Модель | PR-AUC [95 %] | ROC-AUC | срывов среди 1 % самых рискованных |
|---|---|---|---|
| Без модели (доля срывов) | 0,066 | 0,500 | 6 % |
| Baseline мидтерма: логистическая регрессия, 20 признаков | 0,262 [0,246; 0,280] | 0,792 | 50 % |
| Настроенный CatBoost, 20 признаков (A3, ноутбук 04) | 0,311 [0,293; 0,331] | 0,807 | 57 % |
| Qwen2.5-1.5B, дообученная через QLoRA (A3, ноутбук 06) | 0,322 [0,302; 0,342] | 0,808 | 59 % |
| **Финальная модель: CatBoost, 61 признак с текстом лотов (A3, ноутбук 07)** | **0,364 [0,343; 0,385]** | **0,827** | **72 %** |

При бюджете проверок 1 % закупок финальная модель находит ≈ 280 сорванных договоров за две недели против ≈ 196 у
baseline мидтерма. Примерно половина прироста — от семейства модели, половина — от новой информации (в основном текста
лотов); подбор гиперпараметров добавляет мало. Подробности: `reports/A3_report_ru.pdf`.

## Структура репозитория

```
├── data/
│   ├── raw/                        # срез данных OWS (parquet); в git не хранится, скачивается из релиза
│   └── processed/                  # model_table.parquet; в git не хранится, создаётся в A2 или скачивается
├── src/
│   ├── ows_client.py               # клиент GraphQL для OWS v3 (постраничная выгрузка, повторы)
│   ├── collect.py                  # сбор датасета с возобновлением (контакты и счета хранятся только хешами)
│   ├── prepare.py                  # очистка, таблица признаков, target, разбиение по времени
│   ├── features.py                 # A3: победитель без утечки, история «заказчик–поставщик», цена к рынку
│   ├── metrics.py                  # PR-AUC / ROC-AUC на NumPy для кода с torch (проверены против scikit-learn)
│   ├── llm_cards.py, labels_ru.py  # A3: русские карточки закупок для LLM
├── notebooks/
│   ├── 02_data_preparation.ipynb   # A2: качество данных, очистка, EDA, признаки, target, разбиение
│   ├── 03_baseline.ipynb           # мидтерм: базовая модель, метрики, разбор ошибок
│   ├── 04_model_comparison_tuning.ipynb  # A3: 4 модели, перебор + Optuna, порог, калибровка
│   ├── 05a_text_encoders_finetune.ipynb  # A3: transfer learning (3 кодировщика) и fine-tuning (только torch)
│   ├── 05b_text_comparison.ipynb         # A3: TF-IDF против кодировщиков, текст внутри табличной модели
│   ├── 06_llm_qlora.ipynb                # A3: Qwen2.5-1.5B + QLoRA (обучена на Kaggle), оценка, ансамбль
│   ├── 07_results.ipynb                  # A3: финальная модель, таблица всех моделей, абляции, утечка, SHAP
│   ├── build_*.py                  # ноутбуки генерируются из этих скриптов
│   ├── *_ru.ipynb                  # русские версии для чтения (не сдаются)
│   └── make_ru_02.py, make_ru_03.py, make_ru_a3.py (+ ru_a3/)
├── kaggle/06_llm_qlora/            # скрипт дообучения QLoRA, запускаемый на Kaggle через API
├── experiments/a3_pilots/          # пилотные эксперименты, на которых построен план A3
├── results/                        # результаты A3: исследования Optuna, выбранные настройки, журнал и оценки LLM, таблицы
├── reports/                        # proposal, отчёты, слайды (английские и копии *_ru)
├── figures/                        # графики, сохранённые ноутбуками (figures/ru: русские графики для отчёта)
└── collect_supervisor.sh           # перезапускает сбор данных после сбоев сети
```

## Установка

```bash
python -m venv ~/.venvs/tender-risk-ml && source ~/.venvs/tender-risk-ml/bin/activate
pip install -r requirements.txt
```

После этого откройте ноутбук и выполните `Kernel → Restart & Run All`. Пути править не нужно, токен API не нужен:
при первом запуске ноутбуки сами скачивают данные из релиза `data-v1` на GitHub.

## Данные

Источник: OWS v3 GraphQL API (`https://ows.goszakup.gov.kz/v3/graphql`), официальный интерфейс открытых данных
портала госзакупок. Охват: закупки, опубликованные в **I квартале 2024 года**, их лоты, заявки участников, договоры и
реестр недобросовестных участников (РНУ).

| Таблица | Строк |
|---|---|
| `trd_buy` (закупки) | 630 762 |
| `lots` (лоты) | 1 286 364 |
| `trd_app` (заявки) | 1 066 963 |
| `contracts` (договоры) | 555 723 |
| `rnu` (реестр) | 17 343 |

В таблице для моделей 358 789 закупок, по которым есть договор; 6,6 % из них сорвались.

Чтобы собрать срез заново (нужен персональный токен в `.env`, см. `.env.example`):

```bash
python -m src.collect --date-from 2024-01-01 --date-to 2024-03-31
```

Скрипт можно прерывать и запускать снова: он продолжит с места остановки (чекпоинты в `data/raw/_checkpoint.json`).
